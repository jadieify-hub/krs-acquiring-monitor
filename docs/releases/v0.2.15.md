# KRS Эквайринг Монитор 0.2.15

Диагностический выпуск. Поведение программы не менялось.

На кассах повторяются случаи, когда оверлея нет, а приложение не запущено вовсе. Разобрать их по логу было невозможно: любой выход записывался одинаково — `requested`. Теперь причина записывается настоящая.

## Что изменилось

В `diagnostics.log` событие `ApplicationExiting` получает одну из причин:

- `tray` — выход через меню в трее;
- `update` — штатная остановка перед установкой обновления;
- `session-end` — выключение компьютера или выход из Windows;
- `handle-destroyed` — окно оверлея уничтожено посторонней программой, так делает Restart Manager любого установщика;
- `unknown` — ни одна из перечисленных.

Первая установленная причина не переписывается последующими: выключение Windows тоже уничтожает окно, и этот сигнал приходит уже после того, как настоящая причина известна.

## Что делать, если монитор снова окажется не запущен

Соберите на кассе, в сеансе того пользователя, под которым она работает:

```
Get-Content "$env:LOCALAPPDATA\KRS\AcquiringMonitor\diagnostics.log" -Tail 40
```

Последняя строка `ApplicationExiting` теперь называет причину. Этого достаточно, чтобы выбрать исправление вместо догадок.
