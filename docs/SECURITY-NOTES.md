# Технические заметки по безопасности

## Что исследовано

В предоставленной папке SC552 статически изучены имена файлов, PE-заголовки, экспортируемые символы и технические строки журналов. Банковские программы и _2_TEST.bat не запускались.

Локальная pilot_nt.dll:

- версия файла 34.9.3.0;
- PE32/x86;
- экспортирует _get_statistics отдельно от _close_day;
- журналирует оплаты как card_authorize14 → Command 4000 + Department → result/RC;
- журналирует возвраты через Command 4002;
- журналирует закрытие как close_day → Command 6000 → result/RC;
- использует тот же заголовок и результат close_day для запроса статистики Command 7000. Парсер считает закрытием только 6000; 7000 не меняет финансовое состояние.

Сверенный контракт интеграции:

~~~c
#pragma pack(push, 1)
struct auth_answer {
    int TType;
    unsigned int Amount;
    char RCode[3];
    char AMessage[16];
    int CType;
    char* Check;
};
#pragma pack(pop)

int __cdecl get_statistics(struct auth_answer* answer);
~~~

Для краткого текущего отчёта TType равен 0, остальные входные поля нулевые. Check копируется до завершающего NUL и освобождается GlobalFree.

Публичной актуальной официальной документации Сбербанка по этой старой DLL найти не удалось. Для сверки объявления использован открытый пример интеграции, воспроизводящий комментарии и C-сигнатуру SDK: https://github.com/kutsoff/pilot_nt.sberbank/blob/master/PinPad.Pilot_nt.pas. Это вспомогательный, не официальный источник; окончательное подтверждение для конкретной версии выполняется контролируемой приёмкой на кассе.

## Защитные ограничения реализации

Помощник прекращает работу до LoadLibrary, если:

- процесс не x86;
- PE machine DLL не равен 0x014c;
- размер auth_answer не равен 35 байтам.

После загрузки разрешается GetProcAddress только для точной строки _get_statistics. В исходном коде помощника нет делегатов для close_day, card_authorize или LoadParm.

Помощник работает отдельным процессом с тайм-аутом. Главный процесс принимает только полный, однозначно разобранный отчёт. Исходный Check не попадает в diagnostics.log и удаляется из временной папки после чтения.

## Что не следует публиковать

- папку SC552 и её архивы;
- pilot_nt.dll и остальные файлы UPOS;
- pinpad.ini и параметры связи;
- sbkernel/com/commerr-журналы целиком;
- файлы p, SESS.D, SPLC.D;
- необработанный Check;
- PAN, RRN, Merchant ID, Terminal ID, коды авторизации и номера чеков.

Для issue достаточно версии приложения и обезличенных технических строк начала операции, Command/Department и финального result/RC. Суммы при необходимости заменяйте тестовыми, сохраняя формат.

## Граница готовности

Автоматический расчёт проверяется на обезличенных строках реального формата sbkernel. Живой вызов _get_statistics намеренно не выполнялся на копии SC552 без подключённого терминала. Перед промышленным использованием обязательна секция ручной проверки из ACCEPTANCE-CHECKLIST.md.
