# Приёмка на кассе

Проверку выполняйте в спокойное время вместе с ответственным сотрудником. Перед началом сохраните обычный X-отчёт/контрольные суммы штатным способом.

## Установка

- [ ] Установщик 0.2.2 запущен поверх старой версии либо выполнена чистая установка на Windows 10/11.
- [ ] После обновления сохранились настройки, суммы и автозапуск; приложение снова запустилось.
- [ ] Выбрана существующая папка UPOS/SC552, а не её копия внутри приложения.
- [ ] В папке видны pilot_nt.dll, pinpad.ini и актуальный sbkernelYYMM.log.
- [ ] В дистрибутиве нет банковских DLL и журналов клиента.
- [ ] Приложение запускается без прав администратора.

## Оверлей

- [ ] При активном Frontol видны только название и сумма каждой организации и кнопка ↻.
- [ ] Названия и суммы белые, без фона, тени и обводки.
- [ ] При одном отделе видна одна строка; при двух — две.
- [ ] Нет общего итога и номера отдела.
- [ ] Оверлей не закрывает важные элементы Frontol.
- [ ] Его можно передвинуть за название; после перезапуска позиция сохраняется.
- [ ] При появлении окна «Закрытие документа» или другой модальной формы суммы не прыгают.
- [ ] При переходе в другую программу или сворачивании Frontol оверлей скрывается.
- [ ] Прозрачная область не мешает нажимать элементы Frontol.

## Автоматический расчёт

- [ ] До первой операции сумма совпадает с текущим состоянием смены либо показана как неизвестная.
- [ ] Успешная оплата отдела 1 увеличивает только первую организацию.
- [ ] Успешная оплата отдела 2 увеличивает только вторую организацию.
- [ ] Отказ банка не меняет сумму.
- [ ] Успешный возврат уменьшает нужную организацию.
- [ ] Обновление появляется примерно в течение одной секунды после финального ответа банка.
- [ ] Перезапуск приложения сохраняет правильные суммы.
- [ ] После штатного закрытия обеих организаций обе суммы становятся 0,00 ₽.
- [ ] При двух организациях первое закрытие не обнуляет суммы, даже если у второй организации не было операций.
- [ ] Пустые названия позже заполняются автоматически, а введённая вручную подпись не меняется.

## Ручной _get_statistics — обязательная контролируемая проверка

- [ ] В терминале нет активной оплаты/возврата.
- [ ] Зафиксировано, что банковская смена открыта.
- [ ] Нажата кнопка ↻ ровно один раз.
- [ ] Сразу после нажатия видны `…` либо янтарная ↻ и уведомление об отложенном запросе.
- [ ] Отложенный запрос запускается после завершения операции без повторного нажатия.
- [ ] Терминал вернул текущий отчёт без печати через ККТ.
- [ ] После запроса банковская смена осталась открыта.
- [ ] В sbkernel нет вызова close_day/Command 6000 от приложения.
- [ ] Название первой секции отчёта соответствует Department 1.
- [ ] Название второй секции отчёта соответствует Department 2.
- [ ] Суммы оверлея совпадают с банковским отчётом.
- [ ] При двух организациях обе суммы изменились одновременно.
- [ ] После ручной сверки и перезапуска сумма сохраняется, а следующая успешная оплата добавляется ровно один раз.

Если формат не распознан, не меняйте парсер по фотографии с карточными реквизитами. Скопируйте отчёт, удалите PAN, RRN, Terminal ID, Merchant ID, коды авторизации и номера чеков, затем сохраните обезличенный пример для теста.

## Отказоустойчивость

- [ ] При временно недоступном журнале последняя сумма остаётся белой и не обнуляется, а стрелка ↻ становится янтарной.
- [ ] После выбора другой папки UPOS суммы прежнего терминала не показываются.
- [ ] При отключённом терминале ручной запрос показывает понятную ошибку и сохраняет прежние суммы.
- [ ] Нажатие ↻ во время операции откладывается до безопасного момента.
- [ ] Нажатие ↻ между первым и вторым закрытием организаций откладывается до второго закрытия.
- [ ] Автозапуск можно включить и выключить в настройках.
- [ ] В diagnostics.log нет текста банковского отчёта и карточных реквизитов.

## Обновление

- [ ] Portable-копия не выполняет автоматическое обновление.
- [ ] Установленная 0.2.1 получает публичную 0.2.2, перезапускается и сохраняет настройки и автозапуск.
- [ ] Более новая публикация скачивается только под точным ожидаемым именем и запускается после совпадения SHA-256.
- [ ] Повреждённый установщик или манифест не запускается, текущая версия продолжает работу.
